# Architecture Decision Record: D-001 System Boundary & Verification Workflow Integration

* **Status:** Not yet Approved
* **Date:** 2026-08-10
* **Deciders:** Lasswell Mahosi, Jayson Maleya, Siphosethu Tsela, Thobo Modise, Tony Moroke
* **Traceability:** Ensures paperless verification records for Student Welfare and a clear, organized work-order queue for Maintenance Staff.

## 1. Context & Problem Statement
Currently, UB uses a paper-based three-copy verification form involving Student Welfare before a maintenance complaint is sent to the Maintenance Department. The main decision is whether this verification process should be included within the UB-DormHub system or whether UB-DormHub should only function as a maintenance ticketing system.

## 2. Decision Considered
* **Option A (Chosen):** Include Student Welfare verification within UB-DormHub as part of the complaint lifecycle: (`Reported` -> `Verified` -> `Assigned`).
* **Option B (Alternative):** Scope UB-DormHub to handle maintenance dispatch only, requiring Student Welfare to verify complaints outside the system via email/paper before manually injecting work orders.

## 3. Rationale & Choice
We chose **Option A** because the current paper-based and external verification process can result in lost forms, duplicate complaints, and limited accountability. Including verification in UB-DormHub provides end-to-end traceability and allows students to track the progress of their complaints through each stage.

## 4. Consequences & Trade-offs Accepted
* **Positive Consequence:** Eliminates physical paper copies, reduces ticket loss to zero, and provides an unalterable audit trail for management.
* **Trade-off Accepted:** Expands the system's complexity and requires role-based access for Student Welfare, Maintenance Staff, and Students.
